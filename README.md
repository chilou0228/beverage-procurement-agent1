# 酒水全品类智能采销与供应链决策辅助系统

**Beverage Procurement & Supply Chain Decision Support System**

> 基于 Python、Pandas、SQLite、Streamlit 和 Plotly 构建的酒水行业采销与供应链决策辅助系统。通过模拟酒水零售业务数据，整合商品、销售、库存、采购、供应商、竞品价格及促销活动等业务信息，构建覆盖经营分析、采购管理、供应商评价、库存风险识别和促销利润测算的分析与决策支持流程。

**项目类型：** 个人项目 / 规则驱动决策辅助原型  
**开发周期：** 2026.10—2026.11  
**核心技术：** Python、Pandas、NumPy、SQLite、SQLAlchemy、Streamlit、Plotly、PyYAML  
**数据规模：** 300 个模拟 SKU、10 大酒类品类、30 个模拟品牌、40 个模拟供应商、365 天销售数据  
**部署方式：** Streamlit Community Cloud  
**项目数据：** 全部为程序生成的模拟业务数据，不代表任何真实酒类企业、平台、品牌或供应商的经营数据。

## 一、项目背景与建设目标

### 1.1 业务背景

酒水采销业务涉及商品经营、采购计划、供应商管理、库存控制、价格竞争和促销活动等多个环节。

在实际经营过程中，采销人员需要持续关注以下问题：

- **商品经营：** 哪些品类和 SKU 贡献了主要销售额与毛利？哪些商品近期销售表现下滑？
- **采购管理：** 商品应该向哪些供应商采购？不同供应商在报价、供货能力和交货周期方面有什么差异？
- **库存管理：** 哪些商品库存不足，可能影响销售？哪些商品库存积压，需要控制后续采购？
- **供应商管理：** 如何根据实际到货表现、订单完成情况和交付及时性评价供应商？
- **供应链风险：** 主供供应商出现履约风险时，是否存在价格和交期更合适的备选供应商？
- **价格竞争：** 自身商品售价与模拟竞品价格相比处于什么位置？是否存在价格竞争压力？
- **促销决策：** 不同折扣力度会对促销售价、单件毛利、毛利率和预计促销利润产生什么影响？

这些问题分别涉及不同的业务数据。如果只依赖单张 Excel 表格或人工经验进行判断，容易出现数据分散、指标口径不统一、风险识别滞后以及多维度比较效率较低等问题。

### 1.2 项目目标

本项目以酒水全品类零售业务为模拟场景，构建一套面向采销及供应链管理工作的决策辅助原型。

核心目标包括：

1. **建立统一的业务数据体系：** 将商品、销售、库存、采购、到货、供应商、竞品和促销等数据进行结构化组织。
2. **建立经营分析体系：** 从品类、SKU、销售表现、毛利和库存等维度识别经营情况。
3. **建立供应商评价体系：** 根据供货履约、交付及时性和订单完成情况形成供应商综合评分与分级。
4. **建立采购辅助决策规则：** 综合供应商评分、采购报价和交货周期，对主供与备选供应商进行比较。
5. **建立价格与促销分析工具：** 对比模拟竞品价格，测算不同折扣条件下的促销利润变化。
6. **实现交互式业务展示：** 将分析结果整合到 Streamlit 页面中，支持筛选、查询、可视化和数据导出。

项目重点不是单纯展示数据，而是尝试将分散的业务数据转化为可解释、可复用的经营分析和采销决策规则。

## 三、整体业务流程设计

项目将酒水采销业务拆分为五个主要分析环节：

### 3.1 商品经营分析

通过商品基础信息和历史销售数据，识别品类及 SKU 的经营表现。

主要分析：

- GMV、销售额及销售量；
- 商品毛利额与毛利率；
- 访客数及转化率；
- 品类销售贡献；
- SKU 销售趋势及异常变化。

### 3.2 库存与采购管理

将销售表现、库存快照、库存批次和采购订单结合起来，辅助判断商品库存风险及采购执行情况。

主要分析：

- 可用库存及在途库存；
- 安全库存；
- 近 30 天平均日销量；
- 库存可售天数；
- 库存批次及效期信息；
- 采购订单数量、已到货数量和待到货数量；
- 采购订单执行状态。

### 3.3 供应商评价与采购决策

将商品与供应商建立关联，分别识别主供和备选供应商。

通过供应商履约表现、报价及交货周期等维度进行比较，形成供应商评分、分级和采购策略建议。

### 3.4 竞品价格分析

将自身商品售价与模拟竞品报价关联，分析不同 SKU 的价格差异及价格竞争位置，为价格调整和促销策略提供参考。

### 3.5 促销利润测算

根据商品售价、采购成本和促销折扣，计算不同促销方案下的商品利润表现，帮助采销人员判断促销折扣是否合理。

整体业务逻辑：

```text
商品与品类基础数据
        │
        ▼
销售数据分析 ─────── 库存与采购数据
        │                    │
        ▼                    ▼
品类/SKU经营分析       库存风险与采购履约
        │                    │
        └────────┬───────────┘
                 ▼
          供应商评价与分级
                 │
                 ▼
          主供/备选供应商比较
                 │
                 ▼
           竞品价格分析
                 │
                 ▼
           促销利润测算
                 │
                 ▼
        Streamlit 经营决策展示
```

## 四、核心功能模块

### 4.1 经营总览与商品经营分析

**业务问题：** 当前整体经营表现如何？哪些品类和商品值得重点关注？

通过销售明细建立经营指标体系，支持从整体经营、品类和 SKU 等维度观察销售表现。

核心指标：

| 指标 | 计算逻辑 | 业务意义 |
|---|---|---|
| GMV/销售额 | 销售数量 × 销售单价 | 观察商品销售规模 |
| 销售毛利额 | 销售收入 - 商品采购成本 | 观察商品毛利贡献 |
| 毛利率 | 销售毛利额 / 销售收入 | 观察商品盈利水平 |
| 销量 | 销售数量汇总 | 观察商品销售规模 |
| 访客数 | 访客数量汇总 | 观察流量规模 |
| 转化率 | 订单量 / 访客数 | 观察流量转化表现 |

主要功能：

- 汇总核心经营指标；
- 展示日销售额及毛利变化趋势；
- 对比不同酒类品类的销售贡献；
- 分析品类毛利表现；
- 按 SKU 查看销售表现；
- 识别销售下滑或表现异常的商品。

**业务应用场景：**

采销人员可以通过经营总览快速了解不同品类的销售表现，进一步筛选重点 SKU，判断商品是否需要调整采购计划、优化价格或参与促销。

注意：项目中的毛利是基于销售收入与商品采购成本计算的商品毛利，不等同于扣除平台佣金、物流、营销费用后的净利润或贡献利润。

另外，销售数据中的订单量属于模拟数据生成时的近似估算，不应直接视为真实订单系统记录。

### 4.2 SKU 经营诊断

**业务问题：** 某个商品销售表现如何？是否存在价格、库存或供应商方面的问题？

以 SKU 为核心关联商品、销售、库存、供应商、竞品和促销数据。

主要分析内容：

- 商品名称、品类、品牌及规格；
- 商品售价、采购成本和商品毛利率；
- 历史销售额、销量和销售趋势；
- 当前可用库存及库存覆盖天数；
- 主供和备选供应商；
- 供应商报价及交货周期；
- 竞品价格差异；
- 关联促销活动及利润表现。

**业务应用场景：**

当某 SKU 销售下滑时，可以从以下角度进行排查：

1. 查看历史销售趋势，判断是否为短期波动。
2. 查看库存覆盖天数，判断是否存在缺货或库存积压风险。
3. 查看竞品报价，判断自身价格是否存在竞争压力。
4. 查看供应商报价和交期，判断供应链是否存在潜在问题。
5. 查看促销利润测算，评估是否适合通过促销改善销售表现。

该模块将原本分散在多个数据表中的信息整合到单品分析视角，减少人工切换表格和重复查询的工作。

### 4.3 库存健康与风险预警

**业务问题：** 哪些商品可能缺货？哪些商品库存偏高？是否需要调整采购计划？

基于库存快照、近 30 天销售速度和安全库存建立库存风险分析。

核心字段：

- 可用库存；
- 在途库存；
- 安全库存；
- 近 30 天平均日销量；
- 库存覆盖天数；
- 库存成本；
- 商品品类及 SKU 信息。

库存覆盖天数的基本计算逻辑：

```python
inventory_coverage_days = (
    available_stock / avg_daily_sales_30d
)
```

当平均日销量为 0 时，需要单独处理，避免出现除零问题。

主要功能：

- 展示整体库存情况；
- 根据库存覆盖天数识别库存风险；
- 对比可用库存与安全库存；
- 识别低库存、高库存商品；
- 展示库存成本及商品分布；
- 结合库存批次查看生产日期和效期信息。

**业务应用场景：**

- 当库存覆盖天数较低时，提醒采销人员优先检查补货需求。
- 当库存覆盖天数较高时，提醒关注采购节奏和库存积压。
- 当商品库存低于安全库存时，优先检查在途采购和供应商交付情况。
- 对存在效期管理要求的商品，结合批次信息辅助检查库存管理风险。

注意：库存覆盖天数是基于近 30 天平均日销量的静态估算，不能直接等同于未来实际库存可售天数。库存风险阈值属于项目设定的模拟业务规则，需要结合实际企业的商品特性和补货策略调整。

### 4.4 采购订单与到货履约分析

**业务问题：** 采购订单是否按计划执行？哪些订单尚未完成到货？

将采购订单、订单明细和到货记录进行关联，分析采购执行情况。

主要字段：

- 采购订单编号；
- 供应商信息；
- 采购日期；
- 预计到货日期；
- 采购数量；
- 已到货数量；
- 待到货数量；
- 订单状态；
- 商品及品类信息。

采购数量关系：

```text
采购数量 = 已到货数量 + 待到货数量
```

项目通过采购订单明细和实际到货记录汇总，更新订单层面的数量状态。

主要功能：

- 统计采购订单数量和采购金额；
- 查看订单完成、部分到货及在途状态；
- 追踪 SKU 级采购数量；
- 汇总供应商到货表现；
- 识别分批到货和未完成订单。

**业务应用场景：**

采销人员可以通过订单状态了解采购执行情况，及时发现待到货订单，并结合预计到货日期和商品库存情况判断是否需要跟进供应商。

该模块有助于减少人工逐单核对采购明细和到货记录的工作。

### 4.5 供应商综合评价与分级

**业务问题：** 哪些供应商供货表现较好？哪些供应商需要重点关注？

项目根据采购订单明细和到货记录构建供应商评价体系。

评价维度：

| 评价维度 | 权重 | 指标含义 |
|---|---:|---|
| 供货履约率 | 40% | 到期采购数量中已到货数量的比例 |
| 准时交付率 | 35% | 已到货数量中按预计时间到货的比例 |
| 订单完成率 | 25% | 到期订单中全部商品明细完成到货的订单比例 |

综合评分：

```text
供应商综合评分 =
供货履约得分 × 40%
+ 准时交付得分 × 35%
+ 订单完成得分 × 25%
```

当某项评价指标缺少有效数据时，程序会对剩余有效指标的权重进行归一化处理，避免因缺少数据直接影响评分计算。

供应商分级规则：

| 综合评分 | 供应商等级 |
|---|---|
| ≥ 85 | A 级 |
| ≥ 70 且 < 85 | B 级 |
| ≥ 60 且 < 70 | C 级 |
| < 60 | D 级 |
| 无有效评分 | 待观察 |

主要功能：

- 汇总供应商历史采购及到货情况；
- 计算供应商履约率；
- 计算准时交付率；
- 计算订单完成率；
- 形成供应商综合评分；
- 根据评分划分供应商等级；
- 生成差异化合作策略及风险管理建议。

**业务应用场景：**

采销人员可以通过供应商评价结果识别供货表现差异：

- 对表现较好的供应商，可以考虑保持稳定合作。
- 对履约表现不稳定的供应商，可以加强订单跟踪和风险控制。
- 对表现较差的供应商，可以结合实际情况评估采购份额及合作方式。
- 对缺乏有效历史记录的供应商，可以先纳入观察范围。

需要说明：项目中的评分是基于模拟采购和到货数据的规则化评价，并不代表真实供应商信用评级。

此外，准时交付率的计算基于已到货数量，逾期但尚未到货的数量没有直接纳入该指标分母，因此该指标可能高估整体准时交付表现。实际业务应用时应进一步完善逾期未到货的处理方式。

### 4.6 备选供应商推荐

**业务问题：** 主供供应商存在履约风险或价格竞争力不足时，是否有其他可选供应商？

项目为每个 SKU 建立主供与备选供应商关系，综合比较供应商评分、采购报价和平均交货周期。

推荐评价维度：

| 评价维度 | 权重 | 比较内容 |
|---|---:|---|
| 供应商综合评分 | 60% | 供应商历史履约及交付表现 |
| 采购报价 | 25% | 主供与备选供应商报价差异 |
| 交货周期 | 15% | 平均交货天数差异 |

对于缺少有效数据的评价维度，程序会对剩余有效权重进行归一化处理。

主要功能：

- 关联商品主供和备选供应商；
- 比较双方供应商评分；
- 比较采购报价及成本差异；
- 比较平均交货周期；
- 生成备选供应商综合比较结果；
- 根据评价结果输出采购策略建议。

当前系统形成三类决策：

- **维持主供：** 当前主供供应商仍具备相对优势。
- **考虑备选：** 备选供应商在综合评价中具备一定优势，可以进一步评估。
- **暂不推荐：** 当前数据不足或不满足推荐条件。

**业务应用场景：**

当主供供应商出现报价上涨、履约表现下降或交货周期较长等情况时，采销人员可以快速查看备选供应商的报价、评分和交期差异，缩小供应商筛选范围。

该模块输出的是采购决策建议，不会自动替换供应商或自动生成采购订单。实际采购前仍需要结合供应商资质、合同条款、商品质量、供货能力和商务谈判结果进行人工确认。

### 4.7 竞品价格监控

**业务问题：** 自身商品售价与市场参考价格相比处于什么位置？是否存在价格竞争压力？

项目为 300 个 SKU 构建模拟竞品价格数据，每个 SKU 对应 2—4 条竞品报价记录，共计 894 条记录。

主要字段：

- SKU 编号；
- 商品名称；
- 参考品牌；
- 模拟竞品名称；
- 模拟竞品品牌；
- 竞品销售渠道；
- 竞品标价；
- 折扣率；
- 竞品实际报价；
- 自身商品售价；
- 价格差异；
- 价格差异率；
- 价格位置。

主要功能：

- 查看 SKU 对应的竞品报价；
- 比较自身售价和竞品价格；
- 计算价格差异及差异率；
- 区分正常报价与促销报价；
- 分析商品在模拟竞品样本中的价格位置。

**业务应用场景：**

采销人员可以通过价格比较发现自身售价相对偏高或偏低的商品，进一步结合毛利率、库存和销售表现，判断是否需要调整定价或参与促销。

需要注意：竞品名称、品牌和报价均为模拟数据，不代表真实市场价格，也不具备真实市场监测能力。

### 4.8 促销利润模拟器

**业务问题：** 商品参与不同折扣力度的促销活动后，毛利会发生什么变化？是否存在亏损风险？

项目基于商品售价、采购成本和促销折扣构建促销利润测算模块。

核心计算：

```text
促销售价 = 商品原售价 × 促销折扣率

促销单件毛利 = 促销售价 - 商品采购成本

促销毛利率 = 促销单件毛利 / 促销售价

预计促销销售额 = 促销售价 × 预计销量

预计促销毛利 = 促销单件毛利 × 预计销量
```

主要功能：

- 选择待测算商品；
- 调整促销折扣率；
- 设置预计促销销量；
- 自动计算促销售价；
- 计算促销单件毛利和毛利率；
- 测算预计促销销售额和毛利；
- 对比原价销售与促销方案的利润变化；
- 识别促销价格低于采购成本的情况；
- 对低毛利率促销方案进行风险提示。

**业务应用场景：**

采销人员在制定促销方案时，可以先通过模拟器调整折扣力度，观察不同促销价格下的毛利变化。

例如：

- 某商品原售价为 100 元；
- 商品采购成本为 70 元；
- 促销折扣为 90%；
- 促销售价为 90 元；
- 促销单件毛利为 20 元；
- 促销毛利率约为 22.22%。

通过调整折扣率，可以直观判断促销价格变化对单件利润和预计活动毛利的影响。

注意：当前测算主要基于商品售价与采购成本，未完整计入平台佣金、物流费用、营销费用、赠品成本及其他活动费用。因此，测算结果属于商品层面的模拟毛利，不等同于企业实际活动净利润。

预计销量也是输入或模拟参数，并不代表系统已经通过真实实验预测了促销销量提升。

### 4.9 经营决策助手

系统还提供基于预设关键词和规则的经营分析入口。

用户可以输入与经营问题相关的文字，系统根据关键词识别对应业务场景，并调用预设的规则分析逻辑，辅助定位相关指标和数据。

例如：

- 查询库存不足的商品；
- 关注销售下滑的 SKU；
- 查看供应商履约风险；
- 查询备选供应商；
- 分析商品竞品价格；
- 测算促销折扣和毛利。

**当前实现方式：** 规则匹配与预设分析逻辑，不依赖外部付费大模型 API。

因此，本模块属于规则驱动的业务分析助手，而不是基于大语言模型自主规划和调用工具的完整 Agent。

## 十、项目在实际业务中的应用价值

本项目的核心价值在于将采销工作中分散的数据和部分依赖人工经验的判断过程，转化为可查询、可比较、可解释的规则化分析工具。

### 10.1 减少多表查询与人工统计

传统工作中，采销人员可能需要分别打开销售报表、库存表、采购订单表和供应商记录，手动进行筛选、匹配和汇总。

本项目通过统一的数据关联和交互式页面，将相关信息集中展示。

预期价值：

- 减少不同数据表之间的反复切换；
- 降低重复筛选和汇总工作；
- 提高 SKU 和品类信息查询效率；
- 统一部分经营指标的计算口径。

### 10.2 提高供应商比较效率

传统供应商比较可能需要人工整理报价、交期和历史供货情况。

本项目将供应商评分、采购报价和交货周期纳入统一比较规则。

预期价值：

- 减少人工整理供应商评价数据的工作；
- 提高不同供应商之间的横向比较效率；
- 辅助发现潜在备选供应商；
- 为采购谈判和供应商管理提供数据依据。

### 10.3 提前识别库存风险

通过库存覆盖天数、安全库存及在途库存等指标，系统能够辅助识别库存偏低或偏高的商品。

预期价值：

- 减少人工逐个检查库存的工作；
- 帮助采销人员优先关注高风险 SKU；
- 为补货和采购节奏调整提供参考；
- 降低因库存信息分散造成的遗漏风险。

### 10.4 提高促销方案评估效率

促销利润模拟器可以在调整折扣时同步计算促销售价、单件毛利和预计促销毛利。

预期价值：

- 减少反复手工计算；
- 快速比较不同折扣方案；
- 提前识别低毛利和负毛利风险；
- 为促销方案讨论提供统一的数据参考。

### 10.5 将经营分析转化为可复用的决策规则

项目将部分业务判断逻辑固化为可重复执行的程序规则，例如供应商分级、备选供应商比较和促销利润预警。

预期价值：

- 降低重复分析工作；
- 提高分析过程的一致性；
- 增强业务判断的可解释性；
- 为后续接入更复杂的自动化分析能力打下基础。

### 10.6 效率提升如何验证？

目前项目在模拟数据环境下完成了数据处理、业务规则计算、自动化检查和交互式展示，但尚未接入真实企业 ERP、WMS、采购系统或销售后台，也没有开展真实业务人员的对照测试。

因此，当前不能直接声称已经实现某个具体百分比的采购成本下降、库存周转提升或人工效率提升。

若后续应用于真实业务，建议通过以下指标开展验证：

| 验证方向 | 建议指标 | 验证方式 |
|---|---|---|
| 数据查询效率 | 单 SKU 信息查询耗时 | 对比使用系统前后 |
| 报表处理效率 | 单次经营分析耗时 | 对比人工统计与系统分析 |
| 供应商筛选效率 | 单次供应商比较耗时 | 对比人工整理与规则推荐 |
| 库存管理 | 缺货次数、库存覆盖天数 | 上线前后分阶段对比 |
| 采购管理 | 采购订单准时到货率 | 对比相同口径的历史数据 |
| 促销管理 | 促销毛利率、低毛利活动占比 | 比较不同促销方案的实际表现 |

只有在接入真实数据并完成实际业务验证后，才能量化项目的实际效率提升和经营效果。

## 十一、当前项目的实现边界与局限

为了保证项目的真实性和可解释性，当前版本有以下边界：

### 11.1 数据层面

- 所有商品、品牌、供应商、销售、竞品和促销数据均为模拟数据。
- 销售数据覆盖 365 天，库存数据为单日快照。
- 采购订单与到货数据覆盖指定的模拟时间段。
- 竞品价格不来自真实电商平台或市场采集。
- 供应商信息不对应真实企业。

### 11.2 算法与决策层面

- 当前采用规则驱动的分析和推荐逻辑。
- 供应商评分采用预设指标和权重。
- 备选供应商推荐采用预设的综合评价规则。
- 库存预警依赖模拟业务阈值。
- 促销利润测算尚未完整覆盖所有经营费用。
- 规则输出属于辅助建议，不能代替实际采购审批及商务判断。

### 11.3 Agent 能力边界

当前经营助手采用关键词识别和预设规则进行分析，不属于基于大语言模型的自主规划型 Agent。

后续可以进一步升级：

- 引入本地部署的大语言模型；
- 将销售分析、库存分析、供应商评价和促销测算封装为工具；
- 支持模型根据自然语言问题选择对应工具；
- 根据工具执行结果进行多步骤分析；
- 生成结构化经营分析报告。

上述属于后续可扩展方向，不代表当前版本已经实现。

## 十二、项目总结与后续规划

本项目以酒水零售采销业务为背景，完成了从模拟业务数据构建、数据关联、经营指标分析、供应商评价、采购辅助决策到 Streamlit 可视化展示的完整原型开发流程。

通过项目实践，重点探索了以下问题：

1. 如何将酒水全品类商品、销售、库存和采购数据建立关联；
2. 如何通过经营指标识别商品及品类表现；
3. 如何将供应商履约情况转化为可量化的评价体系；
4. 如何结合供应商评分、报价和交期辅助采购选择；
5. 如何将竞品价格和促销利润测算用于经营决策；
6. 如何将分析逻辑封装成可交互、可展示的业务工具。

### 后续迭代方向

| 迭代方向 | 计划完善内容 |
|---|---|
| 数据接入 | 对接真实 ERP、WMS 或销售数据接口 |
| 需求预测 | 引入时间序列预测和安全库存优化 |
| 采购优化 | 加入采购批量、起订量和预算约束 |
| 供应商管理 | 引入质量、退货、异常订单等评价维度 |
| 价格分析 | 接入真实市场及竞品价格数据 |
| 促销分析 | 纳入平台费用、营销成本和实际活动效果 |
| Agent 升级 | 引入本地 LLM Tool Calling，实现自然语言任务分解和工具调用 |
| 报告能力 | 自动生成品类经营、库存风险和供应商分析报告 |

**项目定位：** 一个面向酒水采销业务的规则驱动型经营分析与供应链决策辅助原型。通过结构化数据、业务规则和可视化交互，将商品经营、采购履约、供应商管理、价格比较和促销测算整合到统一的分析平台，为采销人员提供可解释、可复用的决策参考。
